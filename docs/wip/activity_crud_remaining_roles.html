1. How the Draft Was Built

  • Reasoned from the activity. For each activity, the question is what that activity itself creates, reads, updates and deletes. Nothing is inherited from the process.
  • Cross-checked against the old process CRUD. Links the old CRUD never had are marked new; old links no activity supports are marked Not supported.
  • An update implies a read (Q4, Sept 26). An activity that updates a work product is not also listed as reading it.
  • One creating process per work product. Where the old CRUD had a work product created in the wrong process, the create is moved to the activity that actually produces it (Q1). Checked across all 118 activities: no work product is created in more than one process, and every work product has a creator.
  • Outputs the catalog lacks are added when identified (Q5, Sept 26). Ten were added, marked added (Q2). Five smaller outputs are left out and listed for a decision (Q5 below).
  • The ramp shown is the reference Progression Ceiling. The reference baseline is Human-only for every activity.
  • Hover a link to see the reasoning where it is not obvious.

Q1 — Nine old process links no activity supports: corrected

Each comes from the old process CRUD, like CL-006 and the ER Case Record on Sept 26.

  • Workforce Plan is created in 7.1.2.1 Perform strategic workforce planning, not in 7.1.1. 7.1.1’s activities produce the HR strategy, which 7.1.2.1 plans against.
  • Policy Update Record is created in 7.1.2.10 Develop HR policies. 7.1.3.4 Review and revise HR plans updates existing policies rather than creating them.
  • Offer Letter is created in 7.2.4.1 Draw up and make offer, not in 7.2.3. Screening ends with the selection decision.
  • Background Check Record is created in 7.2.5.1 Obtain candidate background information, not in 7.2.4. 7.2.4.3 Hire candidate reads it.
  • Employee Master Record is created at hire, in 7.2.4.3 Hire candidate; 7.7.3 maintains it rather than creating it.
  • Retention Risk Score is created in 7.7.8.2 Develop insights into workforce analytics outcomes, not in 7.5.3. Neither of 7.5.3’s activities (work/life programs and support systems) models attrition. 7.5.1.7 reads it. 7.5.3’s read of the Performance Review goes with it.
  • Performance Review is not updated in 7.3.3. Skill and competency development (7.3.3.3) updates the Development Plan, not the review. This changes a finding in the HRBP Manager’s draft, which saw the review as AI-touched through 7.3.3.3. Without that link, the most automated activity that changes the review is 7.3.2.3 Document employee performance, with an Augmentation ceiling.
Q2 — The ten work products (section 3): added to the catalog

The links rely on all ten. HR Program is one entry for every program 7.1.2 designs (leadership, DEI, talent acquisition, talent development and other programs), so that one creating process holds. The Performance Program and the Onboarding Program stay separate because other processes own and update them.

Q3 — New system category, Document Management System: added

The HR Strategy and HR Program have no system of record among the current categories. Document Management System is added as the generic category, in line with CL-008. The Succession Plan is kept in the Performance Management System, where talent suites usually keep it, rather than adding a Talent Management System category.

Q4 — Performance Program’s creator: 7.1.2.9 Develop other HR programs

Left open on Sept 26. 7.1.2.9 is the only activity that designs an HR program not already named elsewhere, and 7.3.2.4 then monitors and updates it.

Q5 — Five outputs not in the catalog: left out

Each is working material for one activity rather than a record another activity relies on, so they are left out. They are flagged on their activities in section 2:

  • 7.1.1.9 Employer brand content (brand positioning, messaging and assets)
  • 7.2.2.1 A sourcing plan for a requisition (which methods and channels to use)

  • 7.7.8.1 The prepared analysis dataset
