The decision point record

GR-021 made every activity point to a decision point. This sketch gives that decision point a record with a fixed set of fields, and writes it for two decision points, 7.4.4 and 7.6.1.

Fields marked data are read from the sandbox (activity RACI, CRUD, work elements, ceiling, Consequence of Error). Fields marked proposed are my recommended values for you and GiGi to react to.

The fields
  1. Owner — the Human Accountability Anchor, the activity’s Accountable role.
  2. Decides or verifies — the Decide element (or Verify, when there is no Decide).
  3. Work products — what the decision acts on, from the activity’s CRUD, and the other activities that create, update or delete them.
  4. Trigger condition — only where AI leads and a person decides flagged instances.
  5. Escalation path — each condition and the role it goes to.
  6. Override — who can overturn the decision, and how; and how a person setting aside AI output is recorded.
  7. Documentation — what is written down for each decision.
  8. Review cadence — when the decisions are looked at again.

Applying it

A GDP_RECORDS table in pcf7.html, keyed by activity and covered by the change-log audit. The four data fields fill themselves for all 85 decision points; the four written fields are entered per record, Critical and High first. The decision point box in Work shows the record, with each field’s requirement at the activity’s rating, and Findings counts records missing a required field.
