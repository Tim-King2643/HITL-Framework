WR Category Palette Standard

A validated, colorblind-safe color mapping for the six Working-Relationship categories — Automation, Agent-delegation, Augmentation, Oversight, Judgment, Human-only
Documentation Dashboard Work in Progress
Applied — already live. Tim reviewed the before/after comparison and approved this change directly; Oversight and Judgment were respaced across the Working Relationship Progression Table, the PCF 7.0 sandbox, and the Understanding Working-Relationship Progression page the same session. This page is the durable record of why, not a pending request. It also backs the new Rule 20 (WR Category Palette Lock) in the Framework Content Generation Rules.
Token Lock note (Rule 1): Human-only (#0D2D4F) is untouched by this change and stays intentionally identical to the Rule 1 navy-d token — that match is deliberate, not coincidental, and this proposal doesn't disturb it. Automation, Agent-delegation, and Augmentation are also untouched; only Oversight and Judgment move.

Why This Now

The six WR categories were carrying real classification data across all 118 PCF 7.0 activities — the Working Relationship Progression Table and the live sandbox — with no accessibility validation behind the palette and no locked source of truth for it, the same gap Work Pattern Color Standard closed for the five work patterns a few weeks earlier. Reviewing the live badges directly, the three darkest tiers — Oversight, Judgment, Human-only — read as visually similar enough to raise the same question that prompted that earlier proposal: does this actually hold up, or does it just look plain? Running the same rigor (CIEDE2000 color-difference, simulated across deuteranopia and protanopia) gave a real answer rather than an impression.

The Problem

Unlike the work-pattern palette's failure, this isn't a colorblind-specific collapse — the WR ramp is a single hue throughout, so it's already inherently robust to red-green colorblindness; simulated deuteranopia and protanopia barely move the numbers at all. The real issue is perceptual compression at the dark end: CIEDE2000 correctly weights a given lightness step as less significant the darker it gets, so the bottom of a pure-lightness ramp reads as "they all look alike" even when the raw hex values aren't objectively closer together than the lighter tiers.

Measured (CIEDE2000): Oversight vs. Judgment at 6.7 normal / 6.3 deutan / 6.8 protan, and Judgment vs. Human-only at 6.5 / 6.7 / 7.0 — both noticeably weaker than the palette's other three adjacent pairs, which all sit at 10.3–11.4 regardless of vision type.

The Recommendation

Respace Oversight and Judgment only. Pure lightness adjustment can't fix this on its own — CIEDE2000's dark-end compression means a bigger raw lightness step buys less separation than the same step would in the midtones, and Human-only's lightness is fixed to the locked navy-d token. So both moving colors also pick up a bit more saturation and a small hue nudge, giving a second dimension of separation instead of relying on darkness alone. Both stay inside the existing family's hue (~210–216°) and saturation (~46–72%) envelope, so they read as part of the same navy ramp rather than an outlier — a mathematically stronger candidate for Judgment was found and rejected because it pushed saturation to 85% and the hue off-family, which would have looked like a different color entirely.

Build Note

Already applied everywhere this palette was live: the WR_CATS source-of-truth object in the PCF 7.0 sandbox (badges render from it directly, so nothing else in that file needed touching), all 130 hardcoded per-activity swatch instances in the Working Relationship Progression Table, the ramp illustration on Understanding Working-Relationship Progression, and two sandbox UI elements that had independently borrowed Judgment's exact hex (the "Judgment + Oversight" summary pill and the "Modeled" provenance badge) — both updated to match so they don't go stale against the badges around them. Verified live in a headless browser: zero elements anywhere in the three files still resolve to the old colors. The next domain to get a WR rollout inherits this same six-value set with no further validation needed, per Rule 20.
