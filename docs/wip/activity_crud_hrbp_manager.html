1. How the Draft Was Built

  • Every process link is placed. Each create, read, update and delete in the process CRUD is assigned to the activity that does it. None was dropped.
  • Eight processes have a single activity (7.4.1–7.4.4, 7.6.1, 7.8.1 and 7.8.3, plus 7.6.3, whose only activity is 7.6.3.1), so their links move down unchanged. The judgment calls are in 7.2.1, 7.3.2 and 7.6.2.
  • Reads were filled in where an activity plainly uses a work product the process CRUD never recorded. They are highlighted, with the reason under each table.
  • An update implies a read. An activity that updates a work product is not also listed as reading it.
  • Hover a link to see why it was placed there, where that is not obvious.

3. What Changes for the HRBP Manager

The Work Product spec's verification-point rule, run on this draft: a read is a verification point when the work product's producer is at Augmentation or further along the ramp, and the reading activity is at Judgment or Oversight or carries a High or Critical Consequence of Error. Producers outside these eleven processes are still judged at process level.

4. Questions for Tim

Q1 — Two activities create the Separation Record

7.6.2.1 Manage retirement and 7.6.2.3 Manage offboarding both create it, since a retirement is a separation. Keep both as creators, or have offboarding create it and retirement update it? Both are at Automation, so the production mode is the same either way.

Q2 — Does offboarding update the ER Case Record?

The process CRUD says 7.6.2 updates it; the draft places that on 7.6.2.3 (closing any open matter at exit). Because 7.6.2.3 is at Automation, that one update makes the ER Case Record AI-touched, so the HRBP Manager carries a verification point on it in 7.4.2 and 7.4.4. If closing the case at exit is only a status flag rather than a change to the record, the update should go and the ER Case Record stays human-produced.

Q3 — Accept the 12 added reads?

Each is highlighted in its table with the reason. Five give a reader to a work product that had none: the Grievance Case, Separation Record, Policy Update Record, Survey Response and Communication Plan. That cuts the catalog's work products with no recorded reader from 24 to 19.

Q4 — Keep “an update implies a read”?

It keeps the tables readable. The alternative lists the read explicitly every time, which roughly doubles the links on update-heavy activities.

5. What the Draft Surfaced

The Performance Review's AI involvement comes from outside the HRBP's process. Inside 7.3.2, the most automated producer is 7.3.2.3 Document employee performance, at Augmentation. 7.3.2.4, at Agent-delegation, monitors the program rather than producing reviews. The review is still AI-touched at Agent-delegation, but through 7.3.3.3 Manage employee skill and competency development, in the Director of L&D's process, which is still at process level. The spec's pilot sentence that 7.3.2 has “one activity already at Agent-delegation” is true of the process but not of any activity that produces the review.

Six of the eleven processes rest on CRUD not yet confirmed (7.4.2, 7.4.3, 7.4.4, 7.6.1, 7.6.3, 7.8.1). Confirming the links here is the chance to confirm those too.
