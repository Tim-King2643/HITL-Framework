Work Elements

Who does each part of the work at each stage: seven work elements, four lead states, and the stage derived from them
Documentation Dashboard Work in Progress
What this is

A more precise way to say what changes between a person and AI at each step of the ramp. Every activity is broken into the same seven work elements, and each element is led by the person, by AI, or shared. The working relationship is no longer classified as a whole: it is derived from who leads each element. Each element also gets its own ceiling, tied to the ceiling factor that holds it. The result shows up in the Working Relationship info boxes and replaces the five assessment questions in the assessment panel.

1. The problem

The ramp names six working relationships, and each activity has a Current State and a Progression Ceiling. But a stage name says little about the work itself. “Oversight” for a staffing plan does not say whether AI drafts the plan, checks it, records it or shares it, or which of those a person still does. The five assessment questions classify the activity as a whole, so an assessor answering them for a mixed activity has to average in their head.

Writing out who does each part of 7.2.1.1 at each stage made the gap visible, and it found a real error: AI does more of the work in Oversight than in Augmentation, so the two were in the wrong order on the ramp (corrected Oct 6, CL-015).

2. The seven work elements

Every activity is described with the same seven elements. For each one, the activity gives a short phrase saying what that element acts on (“Write the posting text from the requisition and job profile”). An element that isn’t part of the activity is marked as such and points to the activity that owns that work, so nothing is lost between activities.

ElementWhat it coversSets the stage?
ResearchGathering the facts, records and data the work needs.Support
EvaluateAnalyzing them: finding gaps, assessing merit, weighing options.Core
DraftProducing the content of the work: the plan, the answer, the text.Core
VerifyChecking the work against its source, rules and required content.Core
DecideMaking the call or giving the sign-off.Core
Produce / ExecuteRecording, publishing or carrying out the result in the system of record.Support
CommunicateTelling or meeting with the people the result affects.Core

Support elements matter for the work but don’t move the stage on their own: AI keeping the case record does not make a grievance any less of a person’s call.

3. Lead states

Lead stateMeaning
HumanThe person does it alone.
Human-ledThe person does it; AI assists.
AI-ledAI does it; the person approves each instance or handles the ones it flags.
AIAI does it alone.

4. The control element

Every activity has one control element: Decide where the activity has one, otherwise Verify. Who holds the control element separates Oversight, where a person approves every instance, from Agent-delegation, where a person handles only flagged exceptions. In 7.2.1.4 Post job requisitions the decision was made upstream (7.2.1.3), so Verify is the control element.

5. Deriving the stage

The working relationship comes from the elements, top to bottom:

StageWhen
Human-onlyEvery element is Human, or AI touches only Produce / Execute.
JudgmentAI only supplies inputs (Research, Evaluate); the person does the work and makes the call.
AugmentationAI assists in Draft, Verify or Communicate, the person leads every core element, and the control element stays with the person.
OversightAI leads a core element, and a person approves every instance at the control element.
Agent-delegationThe control element is AI-led: a person handles only the instances AI flags.
AutomationThe control element is AI, with no person in the instance.

Because the rule is mechanical, two assessors who agree on the elements always get the same stage, and the reason can be written out: “AI leads Draft; a person approves every instance at Verify.”

6. Element ceilings

Each element has its own ceiling: the highest lead state it may reach. Ceiling factors attach to specific elements rather than to the activity as a whole:

Ceiling factorHolds
Legal / fiduciary dutyEvaluate, Draft, Verify
Human judgment floorDecide
Relational / emotional stakesCommunicate
AccountabilityDraft, Decide

So in 7.4.4 Manage employee grievances, Research and Produce / Execute may go to AI, Evaluate and Verify may be Human-led, and Draft, Decide and Communicate stay Human. The activity’s Progression Ceiling should be the stage its element ceilings allow; the worked examples show they don’t yet agree (section 9). Element ceilings can be proposed automatically from each activity’s ceiling factors and then reviewed.

An organization that runs an element past its ceiling is shown in red at that element, with the factor it breaks. It is recorded as a finding about how the organization works, not an error in the assessment.

7. In the sandbox

Working Relationship info boxes

  • Stage box (click a step): who leads each element at that stage, with the rows that changed from the previous stage highlighted.
  • Gate box (click an arrow): only the elements that change in that step, from and to, with the activity’s own evidence for taking it.
  • Lock box (click the lock): each element’s ceiling and the factor holding it.
  • With an organization selected: the assessed lead state per element with its evidence, past-ceiling elements in red, and the stage derived from them.

Assessment panel

The five assessment questions are replaced by an element grid. For each element the assessor picks the lead state and records the evidence type and a reference; choices above the element ceiling are greyed and show in red if chosen. Current State is derived as the assessor works, with its one-line reason. Source role, confidence and note stay at the activity level. An activity nobody has assessed starts with every element at Human and no evidence, the Human-only baseline, so every step above Human is a choice backed by evidence. The ceiling override section is unchanged (but see section 9).

Existing assessments

ABC Test Org’s saved assessments were made with the old panel. Each is reassessed by element, and its derived stage compared with the stage already saved: any activity where the two differ either finds a flaw in the derivation rule or sharpens its wording.

9. Open questions

Element ceilings and the activity ceiling don’t yet agree — Tim and GiGi

In 7.2.1.1 and 7.4.4 the activity ceiling is Judgment, but the element ceilings let Verify be Human-led in both, and Communicate in 7.2.1.1. AI checking deadlines or drafting a message is AI assisting the work, which the rule derives as Augmentation, a step above the activity ceiling. Either those element ceilings should be Human; or AI help on Verify counts as an input to the person’s own check, which keeps it at Judgment; or the activity ceiling is Augmentation. This needs settling before element ceilings are proposed for the other activities, since it decides whether the activity ceiling is derived from the element ceilings or set on its own.

An element past its ceiling inside an activity within its ceiling — Tim and GiGi

If the two ceilings can differ, how that reads. The sketch shows the element in red even when the activity as a whole is within its ceiling.

Overrides at element level — Tim and GiGi

A ceiling override (GR-054) names the ceiling factor that no longer holds. Since factors now attach to elements, an override might raise only those elements’ ceilings rather than the whole activity’s.

7.2.1.4’s Consequence of Error — Tim and GiGi

Writing out Verify surfaced the pay-range notice. Several states require pay ranges in job postings, so an error carries legal exposure, and Consequence of Error is arguably Moderate rather than Low. The ceiling would stay Automation; the control on Verify must cover the required notices either way.

Where people’s time goes — GiGi

The element view shows what is left for the person at each stage. In 7.2.1.4 at Oversight, it is a review of every posting: per-instance checking of mechanical work, the load the human-impact side looks for. Whether element-level change per role should be part of the role hand-off (GR-056).

The relational factor on Communicate — GiGi

In 7.4.4 the relational ceiling holds Communicate at Human because the person is part of what makes the outcome legitimate to the grievant. Whether that is how the human-impact side would put it, and whether other activities need the same.
