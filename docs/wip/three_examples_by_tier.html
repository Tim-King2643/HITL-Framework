Rules Referenced

Two rules do real work in this chain and are already in use, but haven't had a citable form until now. Both are transcribed here verbatim from their source, not re-derived.

Progression Ceiling Rule — governs the Working Relationship stage

Applied to every one of the 90-plus non-individually-walked activities in the live PCF 7.0 dataset:

  1. Automation is always the floor. Current State = Automation → Future = Ceiling = Automation, always.
  2. A standing accountability duty makes Judgment the ceiling. Strategic authority, EEOC/adverse-impact liability, ERISA fiduciary duty, NLRA/union exposure, or confidentiality/duty-of-care → already at the top; Future = Ceiling = Judgment.
  3. Everything between (Agent-delegation / Augmentation / Oversight): if the item's note flags a standing duty attached to that specific tier, that tier is the ceiling — Future = Ceiling = Current. If no such duty is flagged, the ceiling moves one notch more automated.
Source: inline comment above WR_DATA in docs/sandbox/pcf7.html, "a disclosed heuristic... offered as Claude's own perspective for Tim and GiGi to spot-check and override."
Governed Decision Point definition — governs the Governance Limit stage

Every Governed Decision Point needs to include:

  • Owner — who is named Accountable
  • Escalation — a specific trigger and destination when the owner can't resolve it
  • Override — a defined path to reverse or block an AI-proposed action
  • Documentation — a record of what happened and why
  • Review — a cadence for revisiting the decision or the assignment itself
Source: GiGi Garcia, HITL Working Thoughts & Next Steps, Section 4.

ManagerialHRBP Manager — Manage Leave of AbsencePCF 7.6.2.2
Pattern: Transaction  ·  RACI (7.6.2 Manage separation): A: HRBP Manager · R: HR Generalist · C: Compensation & Benefits Manager · I: Legal*
STAGE 1Working Relationship— checked against the Progression Ceiling Rule
Current: Automation  ·  Future: Automation  ·  Ceiling: Automation. Live note: "routine execution, but FMLA/ADA interference exposure if leave administration is mishandled."
OPEN QUESTION — Rule 1 applies mechanically ("Automation is always the floor... always"), with no carve-out for standing regulatory duty the way Rule 3 has for higher tiers. The note flags real FMLA/ADA exposure sitting on an Automation-tier activity. Proceeding with the live classification as tagged, but this is a real gap in the rule as written, worth raising with Tim and GiGi directly rather than silently resolving it here.
STAGE 2Human Criticality Review— checked against Page 2's six questions
Human impactDirect — job-protected leave status, benefits continuity, and return-to-work rights are at stake.
Legal/regulatoryYes, specifically named — FMLA and ADA interference claims are a well-established litigation category.
Financial/operationalModerate direct cost; litigation cost if mishandled is significant.
Trust/reputationReal internal trust impact — leave failures are exactly the story that damages standing with the workforce.
ReachNarrow per instance (one employee on leave), though volume can be substantial org-wide.
ReversibilityMixed — routine errors are correctable, but an interference finding tied to an adverse action can be very hard to unwind.
HIGH — matches the live tag. Not Critical: the exposure is well-precedented and defensible when procedure is followed, unlike, for example, the grievance activity's NLRB/CBA exposure with less procedural containment.
STAGE 3Human Readiness Gate— checked against Page 1's eight dimensions, for HRBP Manager (Accountable)
AuthorityStrongClear authority to intervene in a leave case.
InformationAdequateCase-level visibility, but FMLA/ADA determinations often need legal nuance beyond standard case data.
CapabilityWeakFMLA/ADA interaction analysis is specialist legal-adjacent judgment; the role is staffed for a largely-automated process, not this expertise on every case.
CapacityStrongRoutine-volume, automated — capacity isn't the constraint.
Role clarityAdequateAccountable per RACI, but no defined point at which an automated case should be pulled out for direct attention.
ConfidenceWeakSame root cause as Capability — not well positioned to challenge an automated system's edge-case handling.
Psychological safetyAdequateNo evidence of penalty risk, but also no established norm for pulling cases out of automation — untested rather than confirmed.
Escalation / overrideWeakLegal is only Informed, not Consulted, despite the note's own FMLA/ADA language. No defined trigger for routing a case to Legal before action is taken.
GATE FAILS — 2 Strong, 3 Adequate, 3 Weak. An Automation-tier, High-consequence activity where readiness to catch exceptions is genuinely weak on the dimensions that matter most: Capability, Confidence, Escalation/override.
STAGE 4Governance Limit— checked against the Governed Decision Point definition
Owner✓HRBP Manager, named.
Escalation✗No defined trigger comparable to the Recruiter example's "comp above band" — nothing tells the process when a case needs to stop for review.
Override✗Not defined.
Documentation✗Not defined.
Review✗Not defined.
1 of 5 elements explicit. Also a second, independent finding: Legal sitting at Informed despite a risk note arguing for Consulted is the same RACI pattern already found once on the grievance activity in the five-activity pressure test — now found twice, which raises it from an isolated note to a pattern worth a standing rule.
STAGE 5Transition Recommendation— synthesis, not a separate check
Hold at Automation for routine processing — the base classification is right for volume reasons — but the ceiling is not closed. Interventions: (1) define a Governed Decision Point for the exception path — Owner: HRBP Manager, Escalation: a named trigger such as "leave nearing exhaustion combined with a performance action, or any ADA accommodation request," Override: Legal review before any adverse action during or immediately after protected leave, Documentation: a case-level record of why an exception was or wasn't escalated, Review: tied to any FMLA/ADA-adjacent incident rather than a fixed calendar; (2) upgrade Legal from Informed to Consulted here — the same correction flagged once already, now recommended as a standing rule rather than a one-off fix; (3) raise the open question from Stage 1 with Tim and GiGi directly: does the Progression Ceiling Rule need a duty carve-out at the Automation tier, the way it already has one higher up?

Where the Chain Held, Where It Didn't

Across the three tiers, the Working Relationship stage held up well — two clean Rule 2 applications (Recruiter, CHRO) and one genuine open question about whether Rule 1 needs the same duty carve-out Rule 3 already has (HRBP Manager). Readiness is where the three diverge sharply: CHRO passes cleanly, Recruiter passes on a bounded-but-functioning governance design, and HRBP Manager fails outright — not because Automation was the wrong base classification, but because nothing catches the exception cases the activity's own note already warns about. The Legal-at-Informed pattern also reappeared independently, now confirmed twice across two unrelated exercises, which is the kind of repeat finding that argues for a standing rule rather than a case-by-case fix.

A person can be named Accountable and still not be able to exercise that accountability — three tiers, and it only failed once, but it failed on exactly the dimensions the framework couldn't have caught without walking the chain.
