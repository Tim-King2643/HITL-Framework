The treemap exhibits show how the composition of each role's remaining human work shifts as AI matures, organized by maturity stage first, pattern second — the same M1/M3/M5 column structure as the treemap itself. This view answers: at this specific stage, across every pattern the role touches, what does the work actually look like? Note that two different percentages appear below: the treemap's box size is each pattern's share of the total remaining workload at that stage (the boxes in each column sum to 100%), while the percentage next to each pattern in the stage detail is that pattern's own human-involvement level, independent of the others.

As AI matures, Recruiter's remaining human work reshapes: Decision claims a growing share, Transaction shrinks toward the margins.

Composition of Recruiter's real activity mix still requiring human involvement, by HITL pattern — area = share, %

Built from Recruiter's real PCF 7.2 RACI data (hitl_dashboard_final.html) — 13 L4 activities across its 3 Accountable processes (7.2.2 Recruit/Source, 7.2.3 Screen and select, 7.2.4 Manage new hire), weighted by activity count × each pattern's M1/M3/M5 human-involvement %. Recruiter has no Exception-pattern activities in current RACI data. Layout: squarified treemap (Bruls/Huizing/van Wijk), each column laid out independently from its own sorted values — box area is the only encoded quantity, position and aspect ratio are layout artifacts.

Source: hitl_dashboard_final.html, PCF 7.2.2–7.2.4 (real RACI/pattern data) — matches Recruiter_Job_Description.docx, recruiter_treemap_mckinsey.html, and pattern_transition_narratives.docx (pattern-first companion view).
