Reference Model and Organization Assessment Layer

The framework describes the work; each organization’s assessment supplies where it stands
Documentation Dashboard Work in Progress
What this is

The framework is a reference model: it describes the work itself — process, RACI, work products, Consequence of Error and a Progression Ceiling for every activity — and no particular organization. Each organization’s assessment supplies its own Current State, activity by activity, and is compared against the ceilings.

  • Sept 26: every activity’s reference Current State is the Human-only baseline (all 118; CL-009).
  • Sept 26: the Reference Model is the default organization in the sandbox, and assessment happens inside its Working Relationship view.
  • Sept 27: the ceiling is called the Progression Ceiling throughout. It is a limit; an organization can raise it only through a governed override (Ceiling Overrides).

1. The problem

The framework describes no specific organization, so it cannot know how any activity is done today. Its old Current State values were modeled judgments of typical practice, shown as if they were readings. What it can say generically is what is true of the work: its consequence of error, the legal, relational and accountability limits on it, and so how far AI may take it. Where a particular organization stands is a fact about that organization.

TermMeaning
Reference modelThe generic content: process structure, RACI, roles, work products and CRUD, Consequence of Error, and the Progression Ceiling for every activity.
BaselineHuman-only: every activity’s starting position in the reference.
Progression CeilingThe furthest along the ramp AI may take the activity, set from its ceiling factors and Consequence of Error.
Assessed Current StateWhere the activity stands in one organization. Exists only in an assessment.
Past the ceilingAn assessed Current State above the ceiling with no override covering it: a finding to resolve, not an error.

Two layers. The reference lives in the sandbox’s master data, in the repo, under the changelog check. Each organization — name, industry, size, whether it is test data — and its assessments live in private storage behind the Worker and the Access login, never in the public repo.

Resolution rule. An activity’s Current State is the organization’s assessed value where one exists, otherwise the Human-only baseline. Its ceiling is the reference ceiling, or the organization’s approved override where one applies.

Granularity. Assessments are made per activity, where the ceiling and consequence live. Process and role figures roll up from activities, with coverage stated (“23 of 118 assessed”). The organization view shows room left for AI, activities past the ceiling, and verification load across roles.

3. What is built

  • The reference reset to Human-only for all 118 activities (CL-009).
  • The organization selector in the sandbox: Reference Model by default, every organization with its coverage, and “New organization…”. ABC Test Org is the test data.
  • Assessment from any activity in the Working Relationship view (assessment template), and ceiling overrides (ceiling overrides).
  • Not yet: ASSESSED source chips (values still read MODELED), coverage on every rollup, the gap view, and access limited per organization.
