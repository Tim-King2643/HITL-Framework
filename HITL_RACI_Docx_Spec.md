# HITL Full RACI Assignment (docx/pdf) — Locked Design Spec

**Status:** Approved by Tim King, August 8, 2026. Companion to `HITL_Maturity_Docx_Spec.md` — this doc type shares the vast majority of its structural/visual conventions with the Maturity doc (both are generated by sibling domain-parameterized scripts and iterated together in the same approval round). This file covers everything specific to the RACI doc; anything not mentioned here should be assumed identical to the Maturity spec.

Canonical spec for `hitl_raci_<slug>_final.docx` across every PCF domain. Generated by the domain-parameter-driven script `gen_domain_raci.js`, invoked as:

```
node gen_domain_raci.js <path-to-domain-json> <output-slug>
# e.g. node gen_domain_raci.js pcf7_full.json pcf7
#      node gen_domain_raci.js pcf8_full.json pcf8
```

The script takes the domain's extracted JSON (code, name, groups[].l3[] with .raci {R,A,C,I} and .l4[]) and produces `hitl_raci_<slug>_final.docx`. All values below are pulled directly from the approved generator source — this file **is** the spec; if the generator ever changes, update this file to match, not the other way around.

### Header row
Same treatment as Maturity: fill 1B4F8A, white bold size 11, **ALL CAPS** (caps:true), **BOTTOM-aligned**. The "A — Accountable" header is two lines — a centered "★" on its own line above "A — Accountable" (via break:1) — everything else is single-line. Bottom-alignment is what keeps the single-line headers sharing a baseline with this one's second line.

## 10. Row hierarchy — RACI has only 2 structural row types (no L1 domain-aggregate row)

RACI data starts at L2 (there's no domain-wide RACI rollup the way Maturity has an M1–M5 aggregate).

### L2 row — single merged banner, not per-column cells
One cell, **columnSpan 7** (spans the entire table width), fill EEF3FA, thinBorder(). Contents: one paragraph, two runs —
- Code run: `"{g.code}  "` (two trailing spaces) — bold, color 0D2D4F (NAVY_D), size 14
- Name run: `g.name` — bold, color 0D2D4F (NAVY_D), size 14

Both runs share identical color/size/weight so the code and name read as one seamless line (an earlier version gave the code prefix a distinct small light-blue Courier New style — corrected, now matches).

### L3 / L4 rows
| Level | Row fill | PCF text | Name text | Pattern column |
|---|---|---|---|---|
| L3 | white / F9FBFD alternating stripe | black 000000, size 13, left, TOP-aligned | 444444, size 14, left, TOP-aligned, no indent | **bar** — identical rule to Maturity §11 |
| L4 | white / FBFCFE alternating stripe | black 000000, size 13, left, TOP-aligned | 444444, size 14, left, TOP-aligned, indent = 260 DXA extra left margin (cell margin) | **colored text badge**, TOP-aligned — identical rule to Maturity §11 |

Both PCF and Name columns are **TOP-aligned**, not centered — this matters more here than in Maturity because R/A/C/I cells can be tall multi-line lists (multiple roles), and top-alignment keeps PCF/Name/Pattern all starting at the same vertical position as the first line of R/A/C/I text, matching the dashboard exactly. (Maturity's M1–M5 cells are always single-line, so this distinction is less visually significant there, but the same TOP alignment is applied for consistency.)

## 11. R/A/C/I cells — the RACI-specific content

Each of the 4 role columns can hold **multiple role names** (multi-line), plus special formatting for parenthetical qualifiers and a "derived from Accountable" fallback. Handled by `raciCellParas()`:

- Values are split on `·` (middot) into separate role entries, each its own paragraph.
- A role entry with a trailing parenthetical, e.g. `"Director of HR Ops (partial)"`, splits into two stacked lines: the role name (color 444444, size 14) and the parenthetical on its own line (italic, color 888888, size 12 — two points smaller than the parent size).
- Empty/`—` values render as a plain em dash, color 999999, size 14.
- **R column fallback**: when a L3/L4 has no separately-confirmed Responsible, the R cell shows the **Accountable** value instead, styled distinctly — italic, color 888888 (dimmed, not the normal 444444) — with one extra trailing line: *"from Accountable"*, italic, color 999999, size 11. This makes clear the value is inherited/derived, not independently confirmed. Controlled by `rCellValue()`, which checks `raci.R` first and falls back to `raci.A` with a `derived:true` flag.
- **A (Accountable) column** always gets a neutral gray-box fill, `F5F5F5`, regardless of row stripe — this visually sets Accountable apart as the "anchor" column, matching the same convention used in the standalone per-stream RACI doc type.
- C and I columns: plain multi-line list, no special fallback or fill.

All four RACI cells share `thinBorder()` and the row's stripe fill (except A, which overrides to F5F5F5).

## 12. Pattern column — identical 3-tier rule to Maturity, minus the L1 dash case

Since RACI has no L1 row, only 2 of Maturity's 3 tiers apply:

- **L3** — always a bar (solid leaf / segmented rollup), same `PATTERN_BAR` medium-tone palette, same fixed-180-twip nested-table rendering, same white segment dividers.
- **L4** — always a colored text badge on pale fill, same `PATTERN_TEXT` / `PATTERN_BADGE_FILL` palettes as Maturity.

There is no dash case in this doc type (L2 doesn't have an individual Pattern cell at all — it's inside the columnSpan-7 banner).

## 13. Borders — identical to Maturity

Same `thinBorder()` / `noBorder()` functions, same segment-divider treatment. See Maturity spec §12.

## 14. Legend — identical to Maturity, different attribution line

Same compact left-packed 5-item legend, same column widths `[1500, 1600, 1600, 1800, 1600]` + spacer. Attribution line differs from Maturity's (no M3/aggregation language, since RACI has no maturity concept):

*"★ A = Accountable · RACI grounded in real APQC L4 activity text · {n L3} confirmed L3 assignments across {n groups} process groups · © Timothy P. King & Claude (Anthropic) 2026"* — italic, color 888888, size 13.

## 15. Colophon / palette — identical to Maturity

Same NAVY/NAVY_D/GRAY/pattern palettes. See Maturity spec §15. (RACI has no DELTA_NEG usage since there's no Δ M1→M3 column.)

## Differences from the Maturity doc — quick reference

| Aspect | Maturity | RACI |
|---|---|---|
| Data columns | M1–M5 + Δ (6 numeric columns) | R/A/C/I (4 role-list columns) |
| Stats card grid | 6 cards, 3×2 | 3 cards, single row |
| Body paragraphs | 2 (narrates M1/M3/Δ) | 1 (narrates methodology only) |
| L1 domain-aggregate row | Yes | No — RACI data starts at L2 |
| L2 row structure | Per-column cells (PCF, name, dash, M-cells, Δ) | Single columnSpan-7 banner (code + name only) |
| A/M3 special column | M3 column highlighted at every level | A (Accountable) column gets neutral F5F5F5 fill at every level |
| Header's two-line column | All of M1–M5 (label + subtitle) | Only "A — Accountable" (★ above) |
| Footer alignment | Centered | Centered (same — differs from the older standalone per-stream RACI doc, which is right-aligned) |

## Build/validation checklist for any new domain

1. Extract the domain's JSON with confirmed `.raci` objects on every L3 (`{R, A, C, I}` strings, multi-role values joined with " · ").
2. Run `node gen_domain_raci.js <domain>.json <slug>`.
3. Convert to PDF and rasterize page 1 for a visual spot check — confirm: banner present, 3-card stats row bordered, ALL-CAPS bottom-aligned header with ★ over Accountable, L2 banner rows read as one seamless code+name line, L3 bars and L4 badges both TOP-aligned and matching Maturity's palette exactly, Accountable column has the gray F5F5F5 fill at every row, R-column fallback (derived-from-Accountable, dimmed italic + "from Accountable" note) renders correctly wherever no separate Responsible exists, legend compact and left-packed.
4. Unzip the output .docx and grep word/document.xml / word/styles.xml to confirm w:jc, w:caps, w:vAlign values and the docDefaults font — never trust a LibreOffice-rendered screenshot alone.
5. Cross-check against `HITL_Maturity_Docx_Spec.md` for the same domain — banner, fonts, borders, Pattern-column palette, and legend should be pixel-for-pixel identical between the two doc types; only the data columns and stats card content should differ.
